## 1. Introduction

Agent reliability is a systems problem. KV management, context compaction,
think-token retention, and session routing are one pipeline; no prior work
measures how serving-layer/context-layer policies affect end-task agent
accuracy end-to-end on open models. (Prior art: Baseten's offline single-model
study, Mar 2026; NVIDIA Dynamo agent-hint telemetry, Apr 2026.)

## 2. Method: two modes

- Mode R — REPLAY (systems metrics; serving axis)
- Mode Q — RE-EXECUTION (accuracy metrics; policy axis P0–P6)
- Bridge: policy decisions carry token accounting → simulated KV footprint →
  measured serving metrics. Headline: the joint accuracy × cost frontier.

## 3. AgentFlight-QA task suite

60 tasks (30 two-hop, 30 three-hop) from 2WikiMultihopQA + HotpotQA (hard),
frozen seed 42, distractor dial {4k, 16k, 32k} total context tokens, 3 tools,
leak-checked at build time. (Suite metadata is generated — see the dataset card.)

## 4. Metrics

TTFT, TPOT, KV bytes/token (derived from model config; Qwen3-8B fp16 =
147,456 B/token), prefix-cache hit rate, cost per completed task, EM + F1,
abandonment, bootstrap CIs (10k resamples, fixed seed). P0 run twice to
quantify run-to-run variance at temperature 0.

## 6. Limitations

Single node, single model family (Qwen3), T4-class hardware, no
disaggregation, client-side timing (localhost), heuristic tokenizer for
policy budgets (model tokenizer on GPU host), 60 tasks → wide CIs.
